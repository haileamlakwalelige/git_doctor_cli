01

The 10 checks

All ten run by default. git-doctor --list-checks prints this sheet from any checkout.

  • ✖ critical
  • ▲ high
  • ⚠ medium
  • • low
  • ℹ info
  1. 01 repo

    Detached HEAD, in-progress operations, unresolved conflicts, uncommitted changes

    ▲ high
  2. 02 dangling

    Commits that are no longer reachable from any branch (lost work)

    ▲ high
  3. 03 branches

    Unmerged work, stale merged branches, branches tracking deleted remotes

    ⚠ medium
  4. 04 sync

    Branches that are ahead of or behind their upstream

    ⚠ medium
  5. 05 large-files

    Oversized blobs stored anywhere in the repository history

    ▲ high
  6. 06 secrets

    Credentials and private keys committed at some point in history

    ✖ critical
  7. 07 ignored-tracked

    Files that are committed yet matched by .gitignore

    ▲ high
  8. 08 config

    Missing git identity, leaked credentials in remote URLs, missing remotes

    ✖ critical
  9. 09 submodules

    Uninitialized, out-of-date or broken submodule entries

    ▲ high
  10. 10 stash

    Stashed changes that may have been forgotten

    ℹ info

* Stamp shows the highest severity the check can report. Descriptions verbatim from git-doctor --list-checks.

02

Safe by design

What git-doctor does — and does not — do to your repository.

  • Read-only

    It never modifies the repository. Every check only reads — after a scan, every byte is exactly where it was.

  • Secrets stay redacted

    Secret values are masked as ghp_ab****** (38 chars) everywhere — in text output and in --json — so reports are safe to share.

  • Runs entirely locally

    No server, no telemetry. The repository never leaves your machine — the whole diagnosis happens in your terminal.

  • Fixes included

    Every finding comes with the exact commands to run to fix it — no guesswork, no link to a documentation page.

03

CI gate

Findings become exit codes your pipeline can already read.

Exit codes

git-doctor exit codes and their meanings
CodeMeaning
0 no findings at or above --fail-on
1 findings at or above --fail-on
2 fatal error, or at least one check failed

$? decides the build — nothing else to wire up.

Workflow step

  run: npx git-doctor --fail-on high
04

Usage

The commands worth remembering, the flags worth knowing.

terminalbash
$ git-doctor path/to/repo --fail-on high
2 findings (1 medium, 1 info) from 10 checks in 2.08s

$ git-doctor --json | jq '.findings[].severity'

$ git-doctor --checks secrets,large-files --history 0

Options worth knowing

--json
machine-readable report, for CI
--checks <ids>
run only the listed checks (default: all)
--skip <ids>
skip the listed checks (default: none)
--history <n>
commits to scan for secrets (default: 200, 0 = full history)
--fail-on <level>
severity that makes the command exit 1 (default: high)
-v, --verbose
also show the checks that passed
-q, --quiet
no output, exit code only
--no-color
disable colors

.gitdoctorignore

test/**            # any check: matching paths
secrets            # every finding of one check
secrets:test/**    # one check: matching paths

Some findings are deliberate. Accepted findings stop affecting the exit code — they are still counted and reported as hidden. Use --no-ignore to see everything.
